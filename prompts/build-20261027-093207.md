### R3. Leaked-password protection
- **Server-side Supabase toggle (Pro only).** Don't upgrade anything yourself.
  - In the final report, tell Hristo in one line that this option exists for $25/month, server-side and impossible to bypass. He decides whether to upgrade later; if he does, it's one toggle: Authentication → Providers → Email (or Attack Protection) → "Prevent use of leaked passwords".
- **Free alternative, implemented now:** add `src/lib/pwnedPassword.ts` with `checkPwnedPassword(password, { fetchImpl?, timeoutMs = 3000, signal? })`. It uses the public Pwned Passwords **k-anonymity range API**:
  - Compute SHA-1 with `crypto.subtle.digest`, as uppercase hex.
  - Call `GET https://api.pwnedpasswords.com/range/{first 5 hex chars}` with the header `Add-Padding: true`.
  - Parse `SUFFIX:COUNT` lines and ignore count-0 padding lines.
  - Return `{ status: 'pwned', count } | { status: 'ok' } | { status: 'unknown' }`.
  - **Fail open:** a timeout, network error or non-200 response gives `'unknown'`, and the form continues as today.
  - **Privacy:** only the 5-character hash prefix ever leaves the browser. Never send, log or store the password or its full hash.
- **Run the check before submitting** on:
  - Signup;
  - the "set new password" form in `ResetPassword.tsx`;
  - the Account password change.
- If the result is `pwned`, block the submit with: "This password has appeared in a known data breach. Please choose a different one."
- Don't change Supabase's password length or character rules: that could raise `WeakPasswordError` for existing users at sign-in.
