## Problem
In demo mode, every ranked result's "Open LinkedIn" button and its copy-able LinkedIn URL point to a fixture URL that does not correspond to a real LinkedIn page. Clicking the button, or pasting the URL into a browser, lands on LinkedIn's "This page doesn't exist" error for every single profile returned by the demo, not just some of them.

## Environment
- Language / framework: TypeScript, React 18 + Vite, running in `VITE_DEMO_MODE=true`
- Relevant file(s):
  - `shared/mocks/fixtures.ts` — `FIXTURE_HOMEPAGES`, `DEMO_SCENARIOS` (source of the fixture people and their LinkedIn URLs)
  - `shared/mocks/mockSearchProvider.ts` — generates `SearchHit`s (including `linkedinUrl`) that feed the pipeline
  - `shared/mocks/random.ts` — seeded-random generator, likely where slugs are built
  - `shared/linkedinUrl.ts` — `normalizeLinkedInProfileUrl`, which may be reshaping/validating these URLs
  - `src/components/ResultCard.tsx` — renders the "Open LinkedIn" button / link and the copy-URL action
- Runtime: browser (desktop + mobile), both light and dark theme — not relevant to the bug itself but confirm the fix doesn't regress either

## Symptom
Every ranked result card shows a LinkedIn URL (e.g. something like `linkedin.com/in/<fictional-slug>`). Clicking "Open LinkedIn" opens that URL in a new tab; LinkedIn returns "This page doesn't exist. Please check your URL or return to LinkedIn home." The same happens if the URL is copied and pasted into any browser. This is 100% reproducible — it happens for every profile in every demo scenario, not an edge case.

## Steps to Reproduce
1. Run the demo (`npm run dev:demo` or open the published demo artifact).
2. Sign up / log in with any demo email.
3. Run a search for any company + position (any of the built-in demo scenarios, e.g. `nimbus-labs.example` + CTO).
4. In the ranked results list, click "Open LinkedIn" on any result card — or copy the LinkedIn URL shown and paste it into a browser.
5. Observe LinkedIn's 404 "This page doesn't exist" page instead of a working profile.

## What I've Already Tried
Not yet investigated — this is a known side effect of how demo fixture data was generated (fictional LinkedIn slugs that were never real profiles), not something already debugged.

## Goal
Every fixture person used in demo mode must have a LinkedIn URL that actually resolves to a live LinkedIn page when opened — for every profile shown, across every demo scenario, not just a subset or a single shared fallback URL for all of them. Pick (and document in a code comment) one concrete approach to get there, for example:
- Replace each fixture person's `linkedinUrl` with a real, currently-live LinkedIn profile URL, OR
- Generate/validate URLs against a known-good set so every one opens successfully.

Whichever approach is used, it must not touch the real (non-demo) pipeline — `shared/rankingSchema.ts`'s whitelist rule that forbids inventing LinkedIn URLs from real search results must remain unchanged; this fix is scoped to the demo/mock data only.

- [ ] Copy-pasting every result's LinkedIn URL into a fresh browser tab also opens a real, existing LinkedIn page.
- [ ] No change to the real (non-demo) search/ranking pipeline or its "never invent a LinkedIn URL" guarantee.
- [ ] Existing tests (`npm test`) still pass, and any test asserting on fixture LinkedIn URLs is updated to match the new values.
