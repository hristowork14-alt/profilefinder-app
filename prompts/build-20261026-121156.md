# ProfileFinder: find the real role holder for any company (multi-strategy verification)

Before any LinkedIn profile is shown, gather and cross-check evidence through several independent strategies. Never show self-declared profiles when evidence names someone else. ### Architecture (single source of truth in `shared/`, used by both the function and the browser demo)
- **`shared/searchService.ts`**: `performSearch` runs these steps in order:
  1. validate
  2. cache (ignored before `cacheValidAfter`, empty results never cached)
  3. rate limit
  4. pipeline
  5. save
  6. cache write
- **`shared/pipeline.ts`**: `runSearchPipeline`, with `DEFAULT_TIMING` set to total 9000 ms, homepage 3000, search 4000, llm 5000, minLlm 1500.
  - **Step 1, at t=0:** the homepage fetch (company name via `shared/companyName.ts`) and the domain LinkedIn query start together. With `corroborate: true` (real app only, set in `netlify/functions/_lib/runtime.ts`), the evidence query `"<Company>" "<position>" -site:linkedin.com` starts at the same time.
  - **Step 2:** the name LinkedIn queries run. Evidence names come from `shared/corroboration.ts` → `extractNamedPeople` (a regex finds capitalized 2–3-word names within 70 chars of the role, needs ≥2 sources, skips "former…"). Each of up to 2 named people is looked up with `site:linkedin.com/in "<Name>" "<Company>"`, and those hits go first.
  - **Step 3:** `filterAndDedupe` cleans the hits. `corroboratedBy` is set via `namesMatch`, which needs the same first and last token.
  - **Step 4:** `rankWithClaude` runs, with an evidence section in the prompt only when corroboration ran. Otherwise `rankHeuristically` runs: a corroborated candidate gets score ≥80; an unconfirmed one is capped at 40 when evidence names someone.
  - **Step 5:** `shared/rankingSchema.ts` applies the zod check plus the **URL whitelist**. Its floor is 20, so anything ≥20 is shown.
- **`netlify/functions/_lib/serper.ts`** returns organic results, plus the answer box, knowledge graph and "People also ask" as extra hits (never displacing organic ones).
- **`netlify/functions/_lib/env.ts`** holds `CACHE_TTL_MS` (7 days) and `CACHE_VALID_AFTER`. **Bump `CACHE_VALID_AFTER` whenever finding or ranking changes**, set to a time just after the deploy.
- **Frontend:**
  - `src/lib/api.ts` has a client timeout of `SEARCH_TIMEOUT_MS = 28_000`.
  - `src/pages/Search.tsx` shows result cards or "No matching profiles found", with the steps company → search → rank.

### Root-cause hypotheses (verify with data; do not assume)
- **H1, nicknames:** the person lookup misses real executives. Possible reasons:
  - the query is too narrow (`"Andy Jassy" "Amazon"`);
  - the Google title of the real profile uses another name form ("Andrew Jassy");
  - the profile is indexed under a different headline;
  - the query timed out, because it starts only after the evidence returns.

  `namesMatch` also fails on nicknames: Andy/Andrew, Bill/William, Ellie/Elinor, Mike/Michael.
- **H2, timing:** the person queries get only the leftover budget, and the total budget (9 s) is too small for multi-step verification.
- **H3, a single fragile evidence query:**
  - one query, using a name derived from the domain;
  - regex-only extraction, which misses "Andy Jassy, president and CEO of Amazon" when the phrasing is unusual, non-English or long;
  - no preference for official sources (the company's own domain);
  - weak recency cues, so a former holder could be counted.
- **H4, a deliberate fallback that is too permissive:** when a verified holder exists but their profile isn't found, self-declared candidates are still returned at ≥20.

## Requirements

### Universal verification, with several strategies before anything is shown
1. **S1, independent evidence from at least 2 parallel queries.** All run with `-site:linkedin.com` and start at t=0. Re-run the queries with the resolved company name if it differs meaningfully from the domain-derived name.
   - `"<Company>" "<position>"` (exists).
   - A natural-language query that triggers Google's answer box and knowledge graph, e.g. `who is the <position> of <Company>`. Use the full title and the abbreviation where synonyms exist.
2. **S2, structured extraction.**
   - **With Claude available:** make one short, time-boxed Claude call that reads the numbered evidence snippets and returns strict JSON, validated with zod: `{ holder: { name, isCurrent, sourceIds[] } | null, alternatives: [...] }`. The rules:
     - only names literally present in the snippets;
     - "former/ex/previous/stepped down/succeeded by" means not current;
     - prefer the most recent dated statement;
     - prefer sources on the company's own domain.
   - **Regex extraction stays.** It is the fallback and a cross-check.
   - **Agreement:** when the two disagree, use the one with more distinct supporting sources. On a tie, treat it as **unverified** (no fake guess).
3. **S3, a robust profile lookup for the verified name.** Run all of these in parallel, with enough budget:
   - `site:linkedin.com/in "<Name>" "<Company>"`
   - `site:linkedin.com/in "<Name>" "<position or synonym>"`
   - `site:linkedin.com/in "<Name>"`, accepting only results whose title or snippet mentions the company or a role synonym
   - the same with known **nickname variants** (Andrew↔Andy, William↔Bill, Robert↔Bob, Elinor↔Ellie, Michael↔Mike, Katherine↔Kate, and so on, as a small general map in `shared/`)

   URLs still come **only** from search results.
4. **S4, profile-quality signals,** read only from search text. Use them only to rank or downgrade, never as proof:
   - followers or connections counts ("1 follower", "0 followers" vs "500+ connections", "10K followers");
   - a missing location or experience;
   - the slug pattern (vanity vs. a long random suffix).

   Never fetch LinkedIn.
5. **S5, a deterministic decision rule in code,** not only in the prompt:
   - **Verified holder V:** a name with ≥2 distinct supporting sources (an official company-domain source counts double), marked current.
   - **If V exists and a profile matches V:** return the V profile(s) only, marked `verified: true`. **Do not return profiles that merely claim the title.**
   - **If V exists but no profile matches:** return `verifiedHolder` with no profiles. The UI shows: "Independent sources say the <position> at <Company> is <Name>. No public LinkedIn profile was found." It lists up to 3 source links taken from the search results (titles and URLs only).
   - **If there is no V:** the current ranking applies, but only results with confidence ≥ 50 are shown, labelled "Not independently verified". Thin self-declared profiles at large companies stay below 50. Otherwise show the existing "No matching profiles found" state.
6. **S6, name matching:** handle nicknames, middle names and initials, accents, "Last, First", and possessives ("Knecht's"), with unit tests.
